# Original technical writing

Use ASD-STE100 Issue 9 as the default for original jehlp.net technical writing.
This includes explanations, instructions, help, interface text, and original mathematical exposition.
The rule applies to new text and substantive edits to existing text.

## Scope and protected content

Classify the text before an edit.

- Rewrite original explanations and instructions at their source.
- Preserve reader text, translations, source quotations, literary passages, and quoted examples.
- Preserve NDB fictional dialogue, story text, bestiary prose, and item descriptions.
- Preserve proper titles, names, citations, legal text, licenses, identifiers, URLs, and code.
- Preserve source data, numerical values, game rules, and scientific uncertainty.
- Preserve equations, formal statements, definitions, hypotheses, quantifiers, and proof dependencies.
- Revise prose inside a proof only when its exact mathematical meaning remains unchanged.
- Keep a historical archive unchanged unless the request explicitly includes that archive.

A translation guide uses this style for its instructions. Its translations retain their required voice.
A writing edit does not authorize a change to behavior, layout, data, or publication settings.

## Write the text

1. Separate instructions from descriptions.
2. Use the imperative for an instruction.
3. Put a prerequisite condition before the instruction.
4. Give one instruction in each sentence, except when actions must occur together.
5. Limit an instruction sentence to 20 words.
6. Limit a descriptive sentence to 25 words.
7. Give each paragraph one topic and no more than six sentences.
8. Use complete grammar, simple verb forms, and active voice.
9. Use passive voice in a description only when the actor is unknown.
10. Use the same term for the same concept.
11. Remove metaphors, idioms, rhetorical questions, and unnecessary words.
12. Do not use semicolons in original prose.

Use short phrases for controls and labels. Keep accessible names consistent with visible labels.
Do not shorten a sentence by deleting a condition, limitation, or required explanation.

## Vocabulary and technical terms

The STE dictionary specifies a word's permitted meaning and part of speech.
A familiar word is not automatically an approved word.
Check general words against the current official dictionary when it is available.

Keep a project glossary for necessary technical nouns and verbs.
Issue 9 permits mathematical and scientific terms, formulas, and subject-specific technical verbs.
It also permits computer and interface terms, such as click, enter, save, sort, and validate.
Use each term in a consistent technical sense.

For proofs, preserve terms such as graph, vertex, cycle, cycle space, rank, forest, and pancyclic.
Preserve distinction between a cycle and an even edge set.
Preserve minimum, maximum, at least, at most, exactly, if, and only if.
Do not replace a precise mathematical term with an approximate everyday word.

## Review and verification

- Compare the revision with the original for complete information and exact meaning.
- Check protected quotations, source data, math, identifiers, and links for equality.
- Review mathematical inferences separately from language and sentence length.
- Rebuild generated HTML, offline exports, search indexes, and PDFs when affected.
- Run the owning repository's tests.
- Review long text, wrapped controls, narrow screens, both themes, and relevant interactive states.

Automatic word counts are screening aids. STE counting rules include special treatment for names,
formulas, units, parentheses, quoted text, and vertical lists. A simple whitespace count is not a full validator.
Report the checks that actually ran. Do not claim certification or complete conformity without full rule and dictionary review.
If the dictionary is unavailable, describe the work as an ASD-STE100-based revision and state that limit in the delivery report.
The public page does not need a compliance banner.
